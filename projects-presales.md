# Projects — Presales

You are working through a fictional client engagement using the BD workflows. Both scenarios come with realistic source material — an RFP from the client — so you have something concrete to work from rather than starting from scratch.

**Each scenario is sized for 90 minutes.** The full BD cycle has six stages; pick the path that fits the time and what you want to practise.

When `/conductor` asks for project type, choose **BD**. This sets up the right folder structure and routes you to the BD workflows.

## Scenario A — Logistics modernisation

**Source material:** [presales-scenarios/scenario-a-logistics/rfp.md](presales-scenarios/scenario-a-logistics/rfp.md)

Read the RFP first. Then run the full cycle — this scenario is scoped to go all the way to a proposal.

**Recommended path (90 minutes):**

```
/conductor → /client-research → /opportunity-qualification → /solution-framing → /offer-estimation → /proposal-writing
```

**What you know going in:**
- The operations director (Mette Sørensen) is the champion but not the budget holder — investments over DKK 2M need board sign-off
- The IT manager (Rasmus Lund) is sceptical about cloud dependency and vendor lock-in
- One previous failed IT project (abandoned mobile app) — internal scepticism is real
- Three vendors are being evaluated in parallel
- SAP S/4HANA integration is a hard requirement
- GDPR compliance is non-negotiable

**Work through:**
- **Client research** — industry context, TransNord's likely technical landscape, stakeholder dynamics, what "winning" looks like for each stakeholder
- **Opportunity qualification** — is this worth pursuing? What are the win conditions? What are the red flags?
- **Solution framing** — what is your approach? What differentiates you from the other two vendors?
- **Offer estimation** — break the solution into work packages. What is the realistic effort and cost range? What are the risk factors?
- **Proposal writing** — assemble a proposal that speaks to Mette and Rasmus separately, addresses the previous failure, and commits to a credible phased approach

**Deliverable:** a complete proposal ready to send — executive summary, solution, integration plan, team, timeline, and investment.

## Scenario B — Public sector data platform

**Source material:** [presales-scenarios/scenario-b-municipality/rfp.md](presales-scenarios/scenario-b-municipality/rfp.md)

Read the RFP first. This scenario is harder — the failure history and fixed-price expectation make qualification and framing the critical work. Go deep on those before moving to estimation.

**Recommended path (90 minutes):**

```
/conductor → /client-research → /opportunity-qualification → /solution-framing
```

If time allows, add:

```
→ /offer-estimation
```

**What you know going in:**
- Two previous failed projects — scope creep and vendor overcommitment both times
- Framework agreement already in place — procurement is simplified, but a fixed-price offer is expected for phase 1
- Seven source systems with varying data quality and mixed API styles (including SOAP)
- Timeline is politically driven by the 2027 local elections, not technical readiness
- IT department has limited capacity (24 staff, significant operational workload)
- GDPR is critical — data includes sensitive social care and elderly care records

**Work through:**
- **Client research** — Danish public sector dynamics, the seven systems landscape, stakeholder map (IT department vs. the six directorates who own the source systems), political vs. technical drivers
- **Opportunity qualification** — given two previous failures, what needs to be true for this to succeed? What would make you walk away? What do you need to know before committing to a fixed price?
- **Solution framing** — how do you position an approach that is credible given the failure history? What do you explicitly commit to and what do you not commit to? How do you frame a phased approach without it sounding like you're hedging?
- **Offer estimation** (if time) — phase 1 scope and effort. What is the right fixed-price approach given the risk?

**Deliverable:** a qualified opportunity assessment with explicit go/no-go reasoning, a solution frame that directly addresses the failure history, and (if time) a phase 1 cost range with risk assumptions.

**The critical question:** should you bid at all? Make an explicit recommendation — don't hedge.

## Tips

- Give the agent the full RFP as context at the start of each stage
- Push back on vague outputs — ask the agent to be more specific, to identify assumptions, to name the risks explicitly
- The interesting moments are when the agent surfaces something you hadn't considered, or when it asks a question that reveals a gap in your thinking
